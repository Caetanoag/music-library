# AGENTS.md

Browser-only music library app: TypeScript + plain HTML/CSS, Supabase REST backend, built with Bun, deployed to GitHub Pages. No framework/bundler config beyond `dev/build.ts`.

## Commands

- `bun install` — install deps (`bun.lock`, frozen in CI).
- `bun run build` — deletes `public/js` and compiles every `src/**/*.{ts,tsx,js,jsx}` into `public/js` preserving paths (`dev/build.ts`, browser target). Minifies only when `NODE_ENV=production`.
- `bun run typecheck` — runs `bun check`. No test suite/runner.
- `bunx biome check src dev` — lint + format + import-order check (no `check`/`lint` script exists). `bun run format` (`biome format --write`, whole repo) only formats (tabs, double quotes); it does not lint.
- `bun run local-serve` — static server for `public/` on a random port; copies localhost URL to clipboard; blocks.
- `bun run serve` — serves `public/`, but copies/prints a QR for the **deployed** GitHub Pages URL (`https://caetanoag.github.io/music-library`), writes `tmpassets/qrcode.png`; blocks.
- `bun run deploy` — `build && serve && format`; `serve` blocks forever so `format` never runs. Don't rely on it in automation.

## Source Layout And Build

- `src/` is source of truth. `public/js/` is generated by `build` and committed—rebuild after changing `src/` and never hand-edit `public/js/`.
- Deployable root: `public/`. Pages: `public/index.html` (login), `public/html/register.html`, `public/html/my-musics.html`, `public/html/all-musics.html`.
- `src/main.ts` is the single shared entrypoint: import all components/page handlers there; every HTML page loads only `js/main.js` (correct relative path). Other generated files (`public/js/my-musics.js`, etc.) are not loaded by any page — loading one too duplicates bundled code and double-registers custom elements.
- Page handlers self-gate: `src/my-musics.ts` / `src/all-musics.ts` bail out unless `document.body.dataset.page` is `my-musics` / `all-musics`. New pages need `data-page` on `<body>` plus an import in `src/main.ts`. Auth handlers attach only when their form id exists.
- Components self-register via `customElements.define` (`<music-card>`, `<custom-header>`, `<custom-footer>`).
- Each `src/` file is a separate build entrypoint with no code splitting. Keep Node/Bun-specific APIs in `dev/` only; TS config: `noEmit`, strict, bundler resolution.

## Deploy And Paths

- Site is served from `/music-library/` on GitHub Pages (not domain root). Use relative URLs in HTML/assets (`css/main.css`, `../js/main.js`), never root-absolute `/...`.
- Push to `main` runs `.github/workflows/static.yml`: `bun install --frozen-lockfile`, `bun run build`, upload `public/` to Pages (Bun `latest` in CI).

## Supabase And Auth

- No `supabase-js`; `src/db/auth.ts` and `src/db/music.ts` call Supabase Auth/REST via `fetch`. Keep that pattern unless asked to add SDK.
- Before editing Supabase communication (`src/db/auth.ts`, `src/db/music.ts`, `src/db/supabase.ts`, request/response handling), read `src/db/schema.sql`: RLS lets any authenticated user read songs but only `added_by` write them; a trigger mirrors new Auth users into `profiles`.
- Supabase URL and publishable key are hardcoded in `src/db/supabase.ts`; no `.env` loading.
- Session stored in `localStorage` as `supabase_session` (access/refresh token, `expires_at`, `user`). Auth pages poll every 2s and redirect to `my-musics.html` when it looks valid; page modules clear it and redirect to login on "não autenticado" errors.
- `MusicDatabase` requires the access token from that session for every call — it throws if absent. The publishable key is only used as the `apikey` header.
- `music-card` fetches cover/album data from public iTunes Search API at runtime; failures/empty results leave fields blank.

## Git And Commits

- Follow Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`...).
- Write commit messages in English.
- Before creating any commit, run `bun run build && bun run format`.
- Before any commit, check `git config user.name`. Only commit if it resolves exactly to `caetano`; otherwise **do not commit** and tell the user to fix the local git identity.
